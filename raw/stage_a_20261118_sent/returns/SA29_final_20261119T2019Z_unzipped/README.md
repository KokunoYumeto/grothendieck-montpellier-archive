# SA29 part 2: guide to the dossier and audit

The ten requested deliverables are at the archive root in the final `SA29.zip`. Stable item identifiers have the form `SA29-n`; claims use `C-SA29-n`; author problems use `MP-SA29-nn`. Gaps in numbering preserve the independently assigned review ranges and any later explicit mergers.

`SA29_entries.tsv` is the complete entry-to-item ledger. The JSON maps distinguish the manuscript statement, a modern reconstruction, textual status and literature status. A bibliography entry marked `verified` means its URL or DOI was opened. `audit/reference_checks.json` records separately whether metadata, a theorem statement, its hypotheses or a proof were actually checked. A modern reference is not treated as the first discovery of a classical result.

Source lines are lines of the named combined `.tex` file unless an entry explicitly says page-local lines. The original notes often cite page-local line numbers. `audit/pages_navigation.json` supplies each scan block's full-file offset; the page-local line1 is the scan command itself. Supplied second-pass corrections form the authoritative reading layer. Input transcriptions have not been edited, and this run has no manuscript images with which to decide new ink questions.

The `review_A`, `review_B`, `review_C` and `review_R` folders preserve the manually authored package records, proof notes, calculation programs and saved outputs. Their initial item maps precede the explicit cross-package mergers in the root deliverables; consult `audit/merge_decisions.json` for the canonical IDs. Serialization programs contain explicit human-readable judgments. They do not classify notes from keywords or generate verdicts from headings.

The compact audit retains search requests, retrieved source identifiers, URLs, failed-access outcomes, source-read ranges and hashes. It omits duplicate bodies of the supplied attachments and external publication caches. Re-running source-reading or retrieval programs requires the original attachment extracted under `sources/` and, for external sources, current network access. Provenance compilers that parse raw retrieval receipts additionally require those receipts; network access alone does not reproduce a historical response. Their compiled search logs and compact request inventories are retained. This avoids bundling whole third-party books and papers into the dossier. Mathematical calculation outputs and this run's proofs are included in full.

To reproduce the consolidated tables, place the final ZIP contents in a directory named `SA29_work`, beside the supplied `sources` tree. The final review registers are the inputs to `code/consolidate.py`; then run `code/build_dossier.py` and `code/validate_dossier.py`. These steps do not require raw web responses. If the earlier review serializers are rerun first, apply `review_R/final_freshness.py` after the other root-review serializers to restore the last verified literature addition. The reference and event ledgers distinguish an opened theorem from an independently checked proof.

`SA29_project_links.tsv` is the separate table of earlier-run project leads. Four availability rows come from the unindexed notes prologue: they retain its file and line instead of inventing an indexed note ID. All indexed source-entry IDs remain accounted for exactly once in the entry-to-item ledger. Number ranges and merged aliases in the overview and directions resolve through the saved alias map.

The bibliography and audit preserve unsuccessful searches without turning a negative result into a proof of nonexistence. Cross-folder and project links whose remote passages were not supplied or retrievable are expressly marked as unverified leads, not completed two-endpoint comparisons. Printed material reused as writing paper is recorded as metadata and is not attributed to Grothendieck.

For a checkpoint, files retain the `SA29_work/` prefix so that they can be restored beside the original `sources/` directory. Checkpoint archives contain all then-written deliverables and review documentation, with the same source-cache exclusions. Prior checkpoints are never nested in a new checkpoint.
