# Reproduction and evidence inventory

All paths in the commands below are relative to this directory. Input transcriptions and notes remain in the supplied sources tree; they are not copied into the final dossier.

1. Complete reading extraction: run python read_source.py J156-9-14 J156-9-15 J156-9-16 J156-9-17 J156-9-18. The saved outputs are read_outputs/J156-9-14.txt through J156-9-18.txt and the original read_log.tsv. These are full line-numbered transcriptions followed by their complete short notes. The extraction script makes no verdict; the model read the entire emitted output.
2. Cross-reference target extraction: python source_checks.py > source_checks.txt. These are full target scans for exact internal cross-reference checks. It does not assert complete reading of other agents' assigned folders.
3. Finite mathematical certificates: python check_ix_examples.py > finite_checks_output.json 2> finite_checks_stderr.txt. The latter file is empty. The code computes lattice operations from the specified orders, checks the primitive clauses of the finite ateliers, and tests the named implications. It records the full eighteen-element order and complement. It is ordinary exhaustive Python, not a proof assistant.
4. The manually authored data are claim_records.py, problem_records.py and ancillary_records.py. No heading, keyword or pattern rule assigns a verdict. Their helpers only format exact scan/line locators and serialize the already assigned fields.
5. Normalize bibliography verification markers: python normalize_bib_notes.py > bib_normalization_output.txt. Full former details move to annote; the note field is exactly verified or unverified. The operation is idempotent. The existing saved output records the first normalization of eight entries.
6. Build the deliverables: python build_deliverables.py > build_output.txt 2> build_stderr.txt. It creates the JSON/TSV files, counts and combined bibliography. It reuses the eighteen checked references from the VI–VII part and adds the eight new entries; the search table expressly distinguishes reused query families from new queries.
7. Formatting repair: repair_proof_format.py was run once, with output proof_format_output.txt. It repaired inline math delimiters lost in initial patch transport and preserved mathematical wording. Its marker prevents a second transformation. The later targeted proof subsection already uses correct dollar delimiters.
8. Structural validation: python validate.py > validation_output.json. The validator checks required fields, IDs, categorical statuses, bibliography markers, source hashes and line ranges, complete supplied scan coverage, query mappings, check events, and the specific saved finite-certificate results. It does not assign mathematical verdicts.

The raw web requests and returned content are search_S9E_01.json through search_S9E_07.json, and open_O9E_01.json through open_O9E_06.json. Every file preserves the request with the returned response; search_log.tsv maps the exact queries to claim families. Shared S67 searches remain in ../cotes_6_7/search_log.tsv and its raw query files, with explicit mappings here.

Routine inspection used ls, cat, sed and rg to inspect these saved outputs and source passages. The full substantive reading output, cross-reference excerpts, mathematical programs, finite outputs and structural-validation output are retained. No mathematical conclusion rests on an unsaved exploratory program. The only independent new computations are those in check_ix_examples.py; all general arguments are written in formalism_and_checks.md.

The bibliographic limits are explicit: R&S exact added-note publication endpoint unavailable; later-volume XIII|XII source absent; full Jenča correction unavailable; original Foulis1960 paper and Gabriel–Zisman1967 book not inspected.
